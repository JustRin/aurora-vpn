# aura-engine

Сетевой движок Aurora VPN на Rust. Заменяет sing-box на Windows: читает тот же
`config.json` и отдаёт тот же Clash API, поэтому приложению и балансировщику всё
равно, какое ядро запущено. Выбор — в настройках приложения, раздел «Ядро».

Это библиотека, и работает она **внутри процесса приложения**: отдельного exe нет, в
диспетчере задач только `aurora-vpn.exe`. Паника в соединении остаётся внутри его
задачи, но аварийное завершение (переполнение стека, сбой в unsafe-коде) теперь
заберёт с собой и окно: за одно на два процесса приходится платить этим. Бинарник
`aura-engine` — та же библиотека с командной строкой, он нужен только стенду.

```bash
npm run wintun                          # wintun.dll в src-tauri/binaries
cargo test --manifest-path engine/Cargo.toml
cargo build --release --manifest-path engine/Cargo.toml   # бинарник для стенда
node engine/tests/stand.mjs             # трафик через настоящие Xray и sing-box
node engine/tests/stand.mjs bench       # сравнение ресурсов с sing-box
node engine/tests/stand.mjs stress      # параллельные запросы, контроль на sing-box
```

## Почему не просто «переписать на Rust»

Язык даёт отсутствие сборщика мусора, но сам по себе лаг раздельного туннеля не
лечит. Поэтому движок устроен иначе в тех местах, где sing-box тратит ресурсы:

| Где sing-box тратит | Что здесь |
|---|---|
| gVisor: TCP-стек в userspace | TCP не покидает ядро ОС: пакеты только переписываются (`inbound/tun/nat.rs`), данные приходят на обычный сокет |
| Таблица TCP/UDP запрашивается на каждое соединение | Снимок на 250 мс, разобранный в хэш (`procinfo.rs`): пачка одновременных соединений стоит одного снятия, TCP и UDP снимаются порознь |
| Правила перебираются списком | Суффиксы — поиск в хэше по родителям имени, гео-наборы — сжатое дерево как в файле |
| 25–35 потоков на любой машине | Не больше 4 рабочих потоков |
| urltest дозванивается до всех узлов каждые 3 минуты | Мерит только пока группой реально пользуются |
| Строка журнала на каждое соединение | Жизнь соединений пишется на DEBUG |
| Паника в разборе чужих байтов роняет процесс | `panic = "unwind"`: падает одна задача, не туннель |

## Замеры

**Память** — настоящий конфиг на 139 узлов, столбец диспетчера задач (private working
set), без TUN. С TUN добавляются кольца Wintun, 2 × 2 МБ.

| | aura-engine | sing-box |
|---|---|---|
| После старта | 1,4 МБ | 17,9 МБ |
| 75 открытых соединений | 9,1 МБ | 21,1 МБ |
| 200 открытых соединений | 16,3 МБ | 26,7 МБ |
| После закрытия всех | 3,8 МБ | 27,2 МБ |

Память движка почти целиком зависит от числа соединений (65–100 КБ на каждое) и
отдаётся обратно. Выигрыш поэтому зависит от нагрузки: огромный в простое и примерно
вдвое, когда открыто много соединений.

**Процессор и скорость** — `stand.mjs bench`, 2026-11-01: 24 ядра, петля, 8 параллельных
скачиваний через вход `mixed`, серверы — настоящие Xray и sing-box, 16 узлов. У sing-box
стоят те же `GOGC=40` и `GOMEMLIMIT`, что и в приложении. TUN этими цифрами **не покрыт**.

| | aura-engine | sing-box |
|---|---|---|
| Размер | 5 МБ кода внутри приложения | 45 МБ |
| Потоков | 6–9 | 24–33 |
| CPU, с/ГБ: VLESS+REALITY+Vision | 1,3–1,6 | 2,1 |
| CPU, с/ГБ: Trojan+TLS | 1,3–1,4 | 2,1–2,3 |
| CPU, с/ГБ: Shadowsocks chacha20 | 1,5 | 2,2–2,4 |
| CPU, с/ГБ: VMess | 1,2–1,3 | 2,1–2,2 |
| CPU, с/ГБ: Hysteria2 | 13–17 | 30–33 |
| CPU, с/ГБ: VLESS без шифрования | 0,7–1,0 | 0,7–0,9 |

Скорость на TCP-протоколах одинаковая (6–7 Гбит/с). Без шифрования выигрыша по CPU
нет: там работает только копирование, и его делает ядро ОС.

**Известный пробел: Hysteria2 под параллельной нагрузкой.** 8 потоков на одном
QUIC-соединении дают 150–585 Мбит/с против 190–930 у sing-box; один поток — около
1,1 Гбит/с. Скорость падает на втором прогоне по тому же соединению, у sing-box тоже,
но позже. На реальном канале не измерялось, причина не установлена.

Читая `bench`, смотрите на колонку «сбоев»: при таком темпе на стенде кончаются порты
(`EADDRINUSE`), и пятый-шестой прогон подряд падает до десятков Мбит/с на любом
движке. Протокол тут ни при чём: при смене порядка жертва меняется. Сравнивать можно
только прогоны без сбоев.

## TLS и REALITY

`tls/stream.rs` — свой клиент TLS 1.3, потому что готовые библиотеки не дают ни
управлять ClientHello побайтно, ни отдать сырой сокет для Vision:

- `tls/hello.rs` собирает hello под отпечаток браузера (Chrome и его наследники,
  Firefox, Safari). Hello без ML-KEM всегда влезает в один TCP-сегмент — это не
  косметика, двухсегментный hello режут ТСПУ на пути из РФ;
- REALITY: метка в `session_id`, проверка HMAC-сертификата. Сервер отверг короткий
  hello — один повторный дозвон с `X25519MLKEM768`, дальше узел ходит с ним. Та же
  логика, что в патче `aurora.2` для sing-box;
- серверы только с TLS 1.2 уходят на rustls: отпечаток там свой, зато соединение есть.

Заголовок протокола всегда уходит одним куском с первыми данными клиента
(`engine.rs::relay`): пакет с одним только заголовком легко распознать по длине.

## Что поддержано

| | |
|---|---|
| Входы | `tun` (Windows), `mixed` (SOCKS5 с UDP, HTTP) |
| Протоколы | VLESS (+Vision), VMess AEAD, Trojan, Shadowsocks AEAD, Hysteria2, SOCKS5, direct, block |
| Транспорт | TCP, TLS, REALITY, WebSocket, HTTP Upgrade |
| UDP | XUDP (VLESS, VMess), Trojan, Shadowsocks, Hysteria2, SOCKS5 |
| Группы | `selector`, `urltest` |
| Правила | процесс, домен, суффикс, ключевое слово, CIDR, `.srs`, private, clash_mode, протокол, тип запроса; sniff, resolve, reject, hijack-dns |
| Сниффинг | TLS, HTTP, QUIC v1, DNS |
| DNS | UDP, TCP, DoT, DoH, system, fakeip; кэш, правила, запросы через прокси идут по TCP |
| Clash API | `/version`, `/connections`, `/proxies`, `/proxies/:tag/delay`, `/configs` |

Узел, который движок не умеет, не роняет документ: он становится заглушкой, замер
честно отвечает «недоступен», и балансировщик его обходит.

## Чего пока нет

Этим пока занимается только sing-box — вернуться на него можно одной кнопкой:

- WireGuard и AmneziaWG, а значит и слой WARP;
- TUIC, транспорт gRPC и HTTP, multiplex;
- Shadowsocks 2022 и устаревшие потоковые шифры (`aes-*-cfb`, `chacha20-ietf`);
- обфускация Salamander и прыжки по портам у Hysteria2;
- `.srs` с логическими правилами (в наборах, что качает приложение, их нет);
- ответ на ICMP-пинг в TUN; `store_fakeip`;
- Linux, macOS и Android: там по-прежнему sing-box и libbox. Движок на них собирается
  (это проверяет CI), но TUN пока есть только на Windows. Чтобы добавить платформу,
  нужны `Device` из `inbound/tun/mod.rs`, маршруты, поиск процесса (`procinfo.rs`) и
  дозвон мимо туннеля (`common.rs`); NAT и UDP общие;
- замер узлов без подключения: его пока ведёт sing-box отдельным процессом, потому что
  движок один на процесс.

Узлы XHTTP и VLESS Encryption, как и раньше, идут через Xray по локальному SOCKS.

## Устройство

```
lib.rs         запуск и остановка внутри процесса
main.rs        командная строка для стенда: run / check / version / match
config.rs      нестрогий разбор документа
engine.rs      путь соединения: правила → исходящий → перекачка
router.rs      правила маршрутизации и DNS
ruleset.rs     бинарные .srs
dns.rs         серверы, кэш, ответы на перехваченные запросы
sniff.rs       имя хоста из TLS, HTTP, QUIC
procinfo.rs    какому процессу принадлежит соединение
tracker.rs     учёт соединений и трафика
api.rs         Clash API
probe.rs       замер задержки
inbound/       mixed; tun: общий NAT и UDP, windows/ — Wintun, маршруты, WFP
outbound/      протоколы и группы
transport/     TCP → TLS → WebSocket
tls/           свой клиент TLS 1.3 и ClientHello
tests/stand.mjs  проверка против настоящих серверов
```
